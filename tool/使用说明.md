# Outlook 取件工具

拉取 `shelbylassila6676@outlook.com` 的收件箱邮件，自动提取**验证码**。已实测可用。

## 快速开始

**双击 `取件.bat`** —— 弹出最新 5 封邮件，每封都标了识别出的验证码。

> 默认**同时扫收件箱和垃圾邮件（INBOX + Junk）**，按时间合并倒序。验证码邮件经常被微软判成垃圾邮件，只查 INBOX 会漏掉最新那封 —— 每封前面的 `[Junk]` / `[INBOX]` 就是它所在的位置。

需要一直守验证码时，**双击 `守验证码.bat`** —— 每 15 秒查一次，取到验证码自动退出。

## 命令行用法

在当前目录打开终端：

```bat
node outlook_mail.js                 最新 5 封(INBOX + Junk)
node outlook_mail.js -n 10           最新 10 封
node outlook_mail.js --code          只输出验证码(便于脚本/程序取用)
node outlook_mail.js -u              只看未读
node outlook_mail.js -m "Junk"       只查垃圾邮件
node outlook_mail.js --scan "INBOX,Junk,Archive"   自定义要扫的文件夹
node outlook_mail.js --raw           正文不截断
node outlook_mail.js --json          机器可读 JSON
node outlook_mail.js --folders       列出所有文件夹
node outlook_mail.js -w 15 --exit-on-code    守验证码
```

也可以用 `取件.bat` 传同样参数，例如 `取件.bat -n 3 --code`。

| 参数 | 说明 |
|---|---|
| `-n, --limit <数>` | 查看最新 N 封，默认 5 |
| `-m, --mailbox <名>` | 只查指定文件夹（默认同时扫 `INBOX` + `Junk`） |
| `--scan <a,b>` | 自定义扫描的文件夹，逗号分隔，默认 `INBOX,Junk` |
| `-a, --account <路径>` | 指定账号文件 |
| `-u, --unseen` | 只看未读 |
| `--code` | 只输出验证码 |
| `--json` | 输出 JSON |
| `--raw` | 正文不截断 |
| `-w, --watch [秒]` | 轮询新邮件，默认 15 秒 |
| `--exit-on-code` | 轮询取到验证码就退出 |
| `--folders` | 列出文件夹名 |
| `--no-cache` | 忽略本地 Access Token 缓存 |
| `--no-save` | 不把轮换后的 refresh_token 写回 |
| `--scope <s>` | 自定义 scope，一般不用 |

`--code` 输出示例（每行一个，最新的在前）：

```text
895721
192182
```

## 账号

账号写在同目录 `account.txt`，一行，用 `----` 分隔：

```text
邮箱----密码----client_id----refresh_token
```

`.bat` 都用 `%~dp0` 取自身目录，所以整个文件夹可以随便移动、改名。

## 工作原理

```text
account.txt 里的 refresh_token
        │  ① POST login.microsoftonline.com/common/oauth2/v2.0/token
        │     scope = https://outlook.office.com/IMAP.AccessAsUser.All
        ▼
   Access Token（1 小时）
        │  ② TLS 连 outlook.office365.com:993
        │     AUTHENTICATE XOAUTH2
        ▼
   INBOX + Junk ──③ 各自 UID SEARCH ALL → UID FETCH(BODY.PEEK[]) → MIME 解码
        │
        ▼
   按 Date 头倒序合并 → 取前 N 封 → 正则识别验证码
```

## 三个坑（已经帮你踩过了）
**1. 必须带 IMAP scope，否则登录一定失败**

只拿 `client_id` + `refresh_token`、不带 `scope` 去换令牌，微软会给你一个属于 Graph 等资源的令牌。用它登录 IMAP，服务器只回一句：

```text
A1 NO AUTHENTICATE failed.
```

必须显式请求 `https://outlook.office.com/IMAP.AccessAsUser.All offline_access`。脚本默认这么做，失败会自动回落到「沿用原授权」再试一次。

**2. refresh_token 会被微软轮换**

每次刷新令牌，微软常常返回一个**新的 refresh_token**，旧的随后失效。脚本拿到新令牌会自动写回 `account.txt`（看到 `[提示] 微软已轮换 refresh_token, 已自动写回 account.txt` 就是发生了）。

所以：**别手工拿旧密钥覆盖 `account.txt`**，也**别两个工具同时用同一份密钥刷新** —— 谁最后刷新谁作数，另一边的令牌就废了。

**3. 最新那封很可能躺在垃圾邮件里**

微软的垃圾邮件判定对「短信转发/验证码」类邮件特别凶。只查 `INBOX` 就会出现「明明刚收到，工具却说没有最新一封」。现在默认 `INBOX + Junk` 一起查、按时间合并排序，每封前面标出 `[INBOX]` / `[Junk]`。

另外 IMAP 的 `UID` 是**每个文件夹各自编号**的，所以跨文件夹不能比 UID 大小，只能比邮件时间 —— 这也是合并时按 `Date` 头排序的原因。

## 常见报错

| 报错 | 原因 / 处理 |
|---|---|
| `AUTHENTICATE failed.` | 令牌没有 IMAP 权限，或 refresh_token 已死。先 `--no-cache` 重试；仍失败就换密钥 |
| `invalid_grant` | refresh_token 失效：被轮换后没保存、改过密码、长期没用。只能重新获取邮箱密钥 |
| `invalid_client` | client_id 和这份 refresh_token 不匹配 |
| `AADSTS90023: No applicable permissions` | 该账号/应用没有邮箱 IMAP 权限 |
| 收件箱为空 | 邮件可能进了 `Junk`，试 `-m "Junk"`；或 `--folders` 看真实文件夹名 |

## 安全提醒

- `account.txt` 里是**明文**密码和 refresh_token，等同于邮箱钥匙：别发群里、别传网盘、别截图。
- 这份 refresh_token 能读写该邮箱（IMAP 权限）。如果它曾经外泄，去 [account.microsoft.com](https://account.microsoft.com) 改密码并重新授权，然后换密钥。
- `.token_cache.json` 里是短期 Access Token，用完可以直接删。
